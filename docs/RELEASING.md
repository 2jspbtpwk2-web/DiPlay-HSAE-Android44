# 贡献、提交与发布

## 提交前

仅在本脱敏源码目录工作；不要把私有完整工作区、build目录或旧Git历史导入。保留来源/许可证和文件级版权。使用合成数据编写测试，禁止贴真实手机身份、配对资料、诊断报告或密钥。

```sh
python3 scripts/check_public_tree.py --tree
# 选择具体需提交文件后，再检查Git暂存区
python3 scripts/check_public_tree.py --tracked
```

无Git目录时默认检查实际树；有Git时默认检查已跟踪/暂存内容。实际树与Git检查都需要，忽略规则不能清理已经跟踪的秘密。工具仅报文件/类别，不应输出真实Token或密钥。新文件/新二进制必须审查，不能为通过扫描随意扩白名单。

## 首次仓库

以脱敏文件建立全新main历史，不把原工作目录整体git add。选择Git提交作者的公开身份/隐私邮箱，不公开本机用户名或私人邮箱。推送前检查暂存文件列表、运行源码安全检查，并确认仓库只含本次允许内容。

本仓库不附个人认证/签名/报告/历史APK或ZIP；GitHub Pages不自动部署旧网站。当前CI只做发布源码检查，不等于应用运行验证。

## APK与Release

第一阶段公开源码，不发布旧私有APK。APK可能包含可提取的运行身份；源码干净不能证明从别处拿来的APK也干净。未来发布APK之前须补齐各运行组件来源与许可、审查最终包所有资产和证书、使用自己私下保管的签名，再对精确产物完成审计、电脑和实车回归。别把签名口令写进脚本/Issue/CI日志。

如秘密曾公开，先撤销/轮换，再按GitHub文档处理历史；只删当前文件或加.gitignore不足。参阅GitHub官方 removing sensitive data 指南。

## 贡献范围

请同时给出车机/系统/USB/解码器信息、版本和脱敏复现步骤。不要把任意OEM的设置写成HSAE通用方案，不以砍等待、变速、删完整PCM或猜CAN来掩盖问题。性能改变附测量边界，认证/控制/生命周期改变需保护正常连接。
